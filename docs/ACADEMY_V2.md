# Academy AI v2 — первый рабочий учебный модуль

> Исторический отчёт о первом этапе. С 04.11.2026 приложение расширено до 20 уроков,
> рабочего планировщика, аналитики, словаря и основы PWA. Актуальные возможности и
> команды находятся в [README](../README.md) и [DEVELOPMENT_REPORT](../DEVELOPMENT_REPORT.md).
> Числа и ограничения ниже относятся к моменту первого этапа.

Продолжение существующего проекта, ветка `feature/academy-ai-v2`.
Исходные модели, демонстрационные данные, Git-история и Streamlit сохранены.

## Что работает

- Один законченный урок A2 **A little every day**: Present Simple, распорядок дня,
  шесть блоков теории, текст для чтения и шесть упражнений.
- Выбор ответа и короткий текстовый ответ. Сервер вычисляет правильность и баллы,
  затем возвращает объяснение. Клиент не может передать готовую оценку.
- Каждый ответ сохраняется сразу. После всех шести ответов прохождение завершается.
- После обновления страницы незавершённый урок продолжается; завершённый показывает
  сохранённый результат и разбор ответов. Несохранённый текст поля при обновлении теряется.
- Повторный одинаковый запрос не создаёт новую попытку. Изменить уже принятый ответ
  внутри прохождения нельзя; после завершения можно пройти урок заново.
- XP равен сумме лучших результатов завершённых уроков, сейчас максимум 60.
  Незавершённые прохождения и старые демонстрационные попытки в XP не входят.
- Разделы «Сегодня», «Обучение», «План», «Прогресс»; светлая/тёмная тема.
  «Сегодня» предлагает следующий шаг, а «План» показывает ориентиры, не фиктивный календарь.
- Адаптивная вёрстка, мобильная нижняя навигация, управление с клавиатуры.
- Нет платных API, Ollama, генерации уроков или исполнения пользовательского Python.

## Запуск из VS Code / PowerShell

Откройте существующую папку проекта. Установленные `.venv` и `frontend/node_modules`
уже подготовлены. Активация окружения и изменение ExecutionPolicy не нужны.

**Терминал 1 — сервер:**

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\applied-is-project-2026'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

**Терминал 2 — интерфейс:**

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\applied-is-project-2026\frontend'
npm.cmd run dev
```

Откройте http://127.0.0.1:5173. API-документация: http://127.0.0.1:8000/docs.
Остановка каждого сервера: `Ctrl+C` в его терминале.

В VS Code выберите **Python: Select Interpreter → .venv\Scripts\python.exe**.
При занятости порта сначала остановите прежний процесс, запущенный для этого проекта.

### Открытие с телефона в одной доверенной Wi-Fi сети

Сервер API оставьте на `127.0.0.1:8000`. Перезапустите только frontend:

```powershell
npm.cmd run dev -- --host 0.0.0.0
```

Vite выведет адрес `Network`, например `http://192.168.1.10:5173`.
Откройте **фактический адрес из терминала** на телефоне в той же сети.
Запросы `/api` проходят через Vite к FastAPI, поэтому `localhost` телефона не используется.
Если Windows блокирует соединение, потребуется разрешить Node.js для частной сети вручную.
Брандмауэр автоматически не меняется.

Это доступ к одной базе на работающем компьютере. Аккаунтов и защиты для публичного
интернета пока нет: используйте только доверенную локальную сеть, без проброса портов.
Облачная синхронизация и офлайн-работа ещё не реализованы. Телефон без доступа к
компьютеру не сможет загрузить урок или отправить результат.

### Установка на другом компьютере

Python 3.13 и Node.js 22.12+ (в работе проверены Python 3.13.15 и Node.js 24.19.0).
Полное проверенное Python-окружение закреплено в `requirements-lock.txt`, npm — в
`frontend/package-lock.json`.

```powershell
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m scripts.prepare_db
Set-Location frontend
npm.cmd ci
```

`requirements.txt` содержит прямые рабочие зависимости; `requirements-dev.txt`
добавляет инструменты тестирования. Streamlit сохранён среди зависимостей.

## База и безопасные миграции

Исходный файл `database.db` продолжает использоваться. Добавлены таблицы:

| Таблица | Назначение |
|---|---|
| `lessoncontent` | Содержание, адрес и версия опубликованного урока |
| `exercisecontent` | Тип задания, варианты, объяснение и допустимые ответы |
| `lessonrun` | Одно прохождение урока, версия содержания и даты |
| `runanswer` | Связь прохождения с исходной таблицей `attempt` |

Исходные `skill`, `lesson`, `exercise`, `attempt` не перестраивались. Новый урок
и упражнения добавлены отдельными записями. Все пять старых попыток сохранены.

Миграции Alembic:

1. `0001_legacy` — проверяет и принимает исходную схему; для пустой базы создаёт её.
2. `0002_learning` — добавляет таблицы v2 и содержимое первого урока.

Предпочтительная команда для будущего обновления **при остановленном API**:

```powershell
.\.venv\Scripts\python.exe -m scripts.prepare_db
```

Она создаёт резервную копию через SQLite backup API, проверяет целостность, выполняет
миграцию на отдельной копии, сравнивает исходные строки и только после успеха обновляет
рабочую базу. Повторный запуск не дублирует урок. DDL и вставка данных выполняются в
явной транзакции. Автоматическое создание таблиц при старте FastAPI отключено.
Разрушительные downgrade-команды намеренно запрещены.

Резервные копии находятся в `backups/`, исключённом из Git. Начальная копия этой работы:
`academy-before-v2-2026-11-03T20-06-15-052Z.db`. Метки файлов содержат UTC; по времени
Asia/Qyzylorda подготовка выполнена 4 ноября 2026 года.
Оригинальная копия содержит 4 навыка, 4 урока, 5 упражнений и 5 попыток.
После миграции: 4 навыка, 5 уроков, 11 упражнений и прежние 5 попыток.

Для восстановления остановите API, сначала сохраните отдельную копию текущей базы
с новыми результатами, затем явно выберите резервную копию для восстановления.
Восстановление старой версии исключит из рабочей базы результаты, полученные после
создания этой копии. Скрипт восстановления автоматически не запускается.

Не используйте OneDrive-копирование открытого `database.db` как синхронизацию устройств.
На следующем этапе стоит перенести рабочие данные из папки исходников в отдельный
каталог приложения. Сейчас расположение сохранено ради совместимости.

Для тестовой или другой базы сервер поддерживает `ACADEMY_DATABASE_URL`:

```powershell
$env:ACADEMY_DATABASE_URL = 'sqlite:///C:/path/to/test.db'
# После проверки верните стандартную базу:
Remove-Item Env:ACADEMY_DATABASE_URL
```

Скрипт миграции принимает путь отдельно:
`python -m scripts.prepare_db --database C:/path/to/test.db`.

## API

| Метод и путь | Действие |
|---|---|
| `GET /api/health` | Готовность схемы БД |
| `GET /api/lessons` | Только опубликованные полноценные уроки |
| `GET /api/lessons/{slug}` | Теория и задания без ключей ответов |
| `GET /api/lessons/{slug}/exercises` | Задания без ключей ответов |
| `POST /api/lessons/{slug}/runs` | Начать или продолжить; тело `{"request_id":"UUID"}` |
| `GET /api/runs/{id}` | Сохранённое прохождение и обратная связь |
| `POST /api/runs/{id}/answers` | Тело `{"exercise_id":6,"answer":"studies"}` |
| `GET /api/lessons/{slug}/stats` | Последний и лучший результаты, активное прохождение |
| `GET /api/progress` | Общая статистика v2 |

Адрес первого урока — `a2-daily-routine`. Числовые ID следует получать из API.
Текст сравнивается без учёта регистра, лишних пробелов, конечных `.?!` и варианта
апострофа. Это проверка конкретного учебного ответа, не свободная AI-оценка речи.
Ключ и объяснение возвращаются только после принятого ответа.

## Проверки

```powershell
# Из корня проекта:
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe -m pytest

# Из frontend:
npm.cmd test
npm.cmd run build
```

Тесты Python создают временные базы. Рабочий `database.db` не используется для записи
тестовых ответов. Проверяются миграции и сохранение исходных записей, отрицательные
сценарии, оценки, конкурентные повторы запросов, восстановление результатов и XP.
UI-тесты проверяют прохождение, восстановление и повтор запроса после сбоя сети.

Сборка TypeScript/Vite и автоматические тесты выполнены. HTTP-проверка подтверждает
связь интерфейса и API через proxy: шесть ответов, пять верных, сохранённый результат
50/60 повторно прочитан. Этот сценарий выполнен на `.test-artifacts/browser-qa.db`,
не на рабочей базе. Пройдены 14 серверных тестов и 3 UI-теста.
Визуальная проверка в браузере не выполнена:
сервис доступа к вкладкам недоступен, запуск окна Chrome через Computer Use завершился
тайм-аутом разрешения. Проверка на физическом телефоне также остаётся ручной.

В Python-тестах есть предупреждение Starlette о будущем переходе с httpx на httpx2;
текущие тесты проходят, зависимости совместимы по `pip check`.

нужно добавить хранение версий содержания, чтобы не менять смысл прошлых попыток.
