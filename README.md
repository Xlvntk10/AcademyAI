# Academy AI

Персональная учебная платформа: английский A2–B2, тренировочный IELTS, основы Python, план до 2028 года и сохранённый прогресс. Продолжение существующего проекта на FastAPI + SQLModel + SQLite, с интерфейсом React + TypeScript + Vite.

Состояние на **18 ноября 2026 года**, ветка `feature/academy-ai-v2`. Работа локальная, для одного человека. Обязательных AI API и платных сервисов нет.

V4 добавляет режим аккаунтов через Supabase Email OTP, серверные сессии, отдельные SQLite-профили и синхронизацию между клиентами. По умолчанию используется существующий локальный профиль. Подключение настоящего провайдера, настройки почты, варианты размещения и результаты проверок описаны в [отчёте V4](DEVELOPMENT_REPORT_V4.md). Профиль открывается по значку «Я».

V4.5 добавляет общую PostgreSQL с изоляцией по владельцу, перенос SQLite, резервное копирование и конфигурацию Render. Инструкция находится в [CLOUD_DEPLOYMENT.md](CLOUD_DEPLOYMENT.md), результаты проверки — в [DEVELOPMENT_REPORT_V4_5.md](DEVELOPMENT_REPORT_V4_5.md). Облачное размещение выполняется отдельно после настройки Supabase. Для выбора PostgreSQL задайте `DATABASE_URL`, для production также `ACADEMY_ENV=production`. Переменная `ACADEMY_DATABASE_URL` имеет приоритет над `DATABASE_URL`.

V5 готовит раздельное размещение React на Render Static Site и FastAPI на Render Free с Supabase PostgreSQL/Auth. Усилены обработка ошибок входа и запрет кеширования личных API-ответов, добавлена проверка опубликованного сайта. Локальная HTTPS-репетиция прошла; внешние сервисы не создавались. Итоги и границы проверки — в [отчёте V5](DEVELOPMENT_REPORT_V5.md), порядок первого размещения — в [CLOUD_DEPLOYMENT.md](CLOUD_DEPLOYMENT.md).

Дополнение V5: вход по **Magic Link** со стандартным письмом Supabase, защита PKCE и переход в профиль. Числовой OTP сохранён как дополнительный способ. Точные настройки для `http://127.0.0.1:5173`, команды запуска и ограничения бесплатной почты — в [MAGIC_LINK_SETUP.md](MAGIC_LINK_SETUP.md).

Проверка нового Supabase Session pooler **без миграций**: [POSTGRES_CONNECTION_CHECK.md](POSTGRES_CONNECTION_CHECK.md). Команда `scripts.check_postgres` показывает ввод URI с `[YOUR-DATABASE-PASSWORD]`, запрашивает настоящий пароль отдельно скрыто, проверяет TLS и выполняет только `SELECT 1`; рабочая SQLite не используется.

V6: подготовлены SQL-план отдельной схемы `academy_stage`, её проверка без личных данных и обязательный TLS `verify-full` для production. Настоящий Supabase на этом этапе не изменён. [План, сохранение 40 XP и откат](V6_CLOUD_DATABASE.md), [отчёт проверок](DEVELOPMENT_REPORT_V6.md).

## Что уже работает

- **Сегодня:** задания из настоящего плана, следующий урок, дневная и недельная цели.
- **Обучение:** По 10 уроков английского A2, B1 и B2, плюс 10 уроков Python: всего 40 уроков и 240 упражнений. Новые уровни открываются последовательно после освоения предыдущих тем (от 80%). Теория, примеры, серверная проверка, объяснения ошибок, повторное прохождение и восстановление результата после обновления страницы.
- **План:** календарь на неделю, доступные минуты по дням, настраиваемое распределение английского и Python (по умолчанию 65/35), перенос заданий, адаптация после пропусков и история. В «Моём маршруте» — целевой месяц IELTS до декабря 2028 года, месячная цель, ориентиры по месяцам и карта освоенных тем.
- **Прогресс:** XP, игровые уровни, streak по Asia/Almaty, 5 достижений, точность ответов, статистика направлений, календарь активности за 12 недель и отчёт текущей недели.
- **IELTS Studio:** 9 авторских тренировок четырёх навыков; 22 объективных вопроса, таймеры, черновики Writing, критерии самопроверки и история. Listening использует локальный синтез речи или текстовый режим. Speaking поддерживает локальную запись и текстовый ответ; band score не вычисляется.
- **Словарь:** 20 слов из уроков, добровольное добавление после прохождения темы, серверная проверка и интервалы повторения 1, 3, 7, 14, 30 дней. Ошибка возвращает слово на завтра.
- Светлая/тёмная тема, адаптивная вёрстка и нижнее мобильное меню.
- Локальная библиотека IndexedDB, офлайн-ответы, очередь и серверное подтверждение без двойного XP.
- Напоминания по выбранным дням, обновления PWA и общий API будущих виджетов.

Исходные модели, демонстрационные попытки, Git-история и `app/frontend/ui.py` со Streamlit сохранены. Старые демонстрационные попытки не считаются учебным прогрессом.

## Запуск в VS Code — PowerShell

В этой папке `.venv`, зависимости, миграции и frontend уже подготовлены. Активация окружения и изменение ExecutionPolicy не нужны.

**Терминал 1, из корня проекта:**

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\academy ai'

$env:ACADEMY_ENV = 'development'
$env:ACADEMY_SERVE_FRONTEND = '0'
$env:ACADEMY_DATABASE_URL = 'sqlite:///database.db'

```

**Терминал 2:**

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\academy ai\frontend'
$env:VITE_ACCOUNT_MODE = 'local'
npm.cmd run dev
```

Открыть **http://127.0.0.1:5173**. API: http://127.0.0.1:8000/docs. Состояние базы: http://127.0.0.1:8000/api/health. Остановка каждого сервера — `Ctrl+C` в его терминале.

Первый полезный сценарий: «План» → «Расписание» → сохранить время → «Составить неделю». Затем пройти урок и в его задании плана отметить фактические минуты. «Обучение» → «Мой словарь» открывает повторение слов.

### Production-сборка и PWA

Сервер FastAPI остаётся запущенным в первом терминале. Во втором, из `frontend`:

```powershell
$env:VITE_ACCOUNT_MODE = 'local'
npm.cmd run build
npm.cmd run preview
```

Адрес **http://127.0.0.1:4173**. В поддерживаемом браузере можно использовать пункт установки приложения либо кнопку в настройках Academy AI, если браузер её предоставляет. Service Worker регистрируется только в production и в защищённом контексте. В режиме разработки на 5173 он не регистрируется. После новой сборки закрой старые вкладки приложения, чтобы ожидающий Service Worker смог обновиться.

Кешируются HTML, JS, CSS, иконки и манифест. В разделе «Локальная библиотека» можно заранее скачать урок, читать теорию и сохранять ответы в IndexedDB. Очередь отправляется при доступном FastAPI и открытом приложении. Проверку ответов и XP подтверждает сервер. Новая версия PWA показывается уведомлением и применяется из настроек.

Исправлена воспроизведённая пустая страница при автономном открытии: кеш публичных ресурсов теперь учитывает различие запросов precache и ES-модулей при `Vary: Origin`. Во встроенном браузере проверены открытие новой вкладки после закрытия вкладок приложения и остановки обоих тестовых серверов, все четыре основных маршрута, урок из IndexedDB, черновик и отправка очереди после восстановления серверов. 18 ноября дополнительно проверен запуск нового процесса headless Chrome после остановки тестовых серверов: все четыре маршрута показывают офлайн-экран. Установка и запуск с иконки, а также настоящий телефон пока не проверены. Перед поездкой проверь автономный запуск на своём устройстве. Подробности и инструкция безопасного обновления — в [отчёте об исправлении офлайн-запуска](PWA_OFFLINE_FIX_REPORT.md); общие инструкции установки — в [отчёте V3](DEVELOPMENT_REPORT_V3.md).

### Открыть интерфейс на телефоне в своей Wi-Fi сети

FastAPI можно оставить на `127.0.0.1:8000`: Vite проксирует `/api`. Запусти frontend так:

```powershell
npm.cmd run dev -- --host 0.0.0.0
```

Открой на телефоне адрес `http://<IPv4-компьютера>:5173`, показанный Vite. Компьютер должен оставаться включённым, устройства — в одной доверенной сети. Если Windows запросит доступ, достаточно частной сети. В описанном локальном режиме вход отключён: не открывай его в публичный интернет и не настраивай проброс портов. Режим аккаунтов Supabase включается отдельно. Этот режим использует одну базу на компьютере и принимает локальную очередь попыток. Для PWA на телефоне нужен доверенный HTTPS. Поддержка собственных сертификатов через `ACADEMY_HTTPS_CERT` и `ACADEMY_HTTPS_KEY` описана в [отчёте V3](DEVELOPMENT_REPORT_V3.md).

## IELTS и долгосрочный маршрут

В «Обучении» открой **IELTS Studio**, либо используй карточку на главной. Внутри — Listening, Reading, Writing и Speaking. Черновик автоматически сохраняется после паузы во вводе; есть отдельная кнопка сохранения. При сетевой ошибке остаётся локальная текстовая копия. Конфликтующие версии показываются для выбора, а не молча перезаписываются.

Для Listening нужен установленный локальный английский голос. Если его нет, открой текст: результат помечается текстовым режимом. В Speaking микрофон включается только по кнопке и с разрешения браузера. Аудио хранится в IndexedDB этого браузера, не в SQLite и не на другом устройстве. Его можно прослушать и скачать. Очистка данных браузера удаляет локальную запись. HTTPS или localhost нужны для микрофона; по обычному HTTP-адресу компьютера на телефоне используй текстовый режим.

В «Плане» открой **План до IELTS**, выбери месяц, процент английского и цель месяца. Уже составленную неделю нужно обновить для новой пропорции. Кнопка **Подстроить после пропусков** заменяет будущие неначатые задания переносами пропущенных; сохраняет завершённые, начатые уроки и ручные переносы. Если времени не хватает, остаток честно остаётся пропущенным.

## База данных и безопасное обновление

Рабочий файл: `database.db` в корне. Версия схемы: `0009_offline_sync`. `ACADEMY_DATABASE_URL` позволяет явно выбрать другую SQLite-базу для тестирования; обычный запуск не требует переменных окружения.

Перед будущими миграциями останови API и Streamlit. Выполни из корня:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.prepare_db
```

Скрипт проверяет целостность, делает резервную копию через SQLite backup API, применяет миграцию сначала на отдельной копии и сравнивает все существовавшие записи и столбцы. Только затем обновляет рабочую базу. Копии остаются в `backups/`. Ничего не удаляется автоматически. При несовместимой схеме обновление останавливается. Автоматического разрушительного downgrade нет.

Не запускай `seed.py` для наполнения v2 и не удаляй базу. Учебный контент устанавливается миграциями. Резервные копии и база исключены из Git. Папка находится в OneDrive: не используй один SQLite-файл одновременно с двух компьютеров через файловую синхронизацию.

## Проверки

Из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest --basetemp .test-artifacts/pytest
.\.venv\Scripts\python.exe -m pip check
Push-Location frontend
npm.cmd test
npm.cmd run build
Pop-Location
git diff --check
```

Проверено в V5: **99 серверных тестов** (включая 16 с реальной локальной PostgreSQL), **56 frontend-тестов**, TypeScript, production build, целостность SQLite и сохранение существующих данных при миграции. Есть одно предупреждение Starlette об устаревающей поддержке `httpx` в TestClient; оно не приводит к падению тестов.

Для полного набора PostgreSQL-тестов нужны отдельная база с именем, заканчивающимся на `_test`, переменные `ACADEMY_TEST_DATABASE_URL`, `ACADEMY_TEST_ADMIN_URL` и путь `ACADEMY_TEST_PG_BIN` к pg_dump/pg_restore. Без этих параметров интеграционные проверки пропускаются. Никогда не подставляйте рабочую базу.

Для проверки настоящего HTTP-запуска, когда порты 8000 и 4173 свободны (frontend предварительно собран с `VITE_ACCOUNT_MODE=local`):

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.smoke_http
```

Скрипт создаёт копию рабочей базы в `.test-artifacts/`, запускает свои локальные серверы, проходит урок через Vite proxy, проверяет план, словарь, IELTS Reading и черновик Writing, перезапускает API и сравнивает сохранённый результат. Проверяет ресурсы PWA, офлайн-попытку и повторную отправку после перезапуска API. Останавливает собственные процессы. Для занятых стандартных портов доступны параметры `--backend-port 8105 --frontend-port 4275`. Рабочая база не используется для тестовых ответов.

## Как устроен проект

```text
app/database/         исходные модели + добавочные учебные таблицы
app/routers/          уроки, план, аналитика, словарь
app/services/         проверка ответов, расписание, статистика, время
app/*_schemas.py      входные и выходные структуры API
app/frontend/ui.py    сохранённая заготовка Streamlit
frontend/src/         React-интерфейс и компонентные тесты
frontend/public/      PWA-манифест и иконки
migrations/versions/  последовательные миграции Alembic
migrations/data/      версии учебного контента
scripts/prepare_db.py безопасное обновление базы
scripts/smoke_http.py HTTP-проверка на копии
tests/                серверные и миграционные тесты
backups/              локальные резервные копии, вне Git
```

Правильность, баллы, интервалы повторения и XP определяет сервер. XP за уроки — сумма лучших завершённых результатов, а не сумма повторных прохождений. За самостоятельную практику — максимум 10 XP на направление за календарный день. Минуты берутся из твоих отметок в плане. Игровой уровень не является оценкой IELTS. Пользовательский Python-код не исполняется.

## Ограничения и дальнейшая работа

Локальная очередь поддерживает объективные уроки английского и Python. IELTS, план и общая статистика требуют подключения. Авторизация и разделение аккаунтов проверены локально через тестовый HTTP-провайдер, подключение реального Supabase и публичного backend остаётся этапом развёртывания. Web Push, нативные виджеты и University Tracker остаются будущими задачами. Проверка текста IELTS ограничена учебными рекомендациями. Оценка произношения требует отдельной реализации.

В браузере проверены сохранение ответов при недоступном API, восстановление черновика, отправка очереди и результат на ширине 390 px. На эмулируемой ширине 390 px горизонтального переполнения нет. Холодный запуск проверен в новом процессе headless Chrome; установка PWA и автономный запуск на физических устройствах требуют ручной проверки.

Текущий [отчёт V3](DEVELOPMENT_REPORT_V3.md) содержит инструкции установки и ограничения. Отдельно подготовлен [план облачной синхронизации](CLOUD_SYNC_PLAN.md). История этапов сохранена в [DEVELOPMENT_REPORT_NEXT.md](DEVELOPMENT_REPORT_NEXT.md) и [DEVELOPMENT_REPORT.md](DEVELOPMENT_REPORT.md).
