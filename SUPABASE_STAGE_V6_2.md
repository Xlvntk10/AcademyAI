## Разрешение и реализация

В текущем чате пользователь отдельно подтвердил: «Разрешаю это узкое право SET».
Объём: только `GRANT academy_stage_runtime TO CURRENT_USER WITH SET TRUE,
INHERIT FALSE` внутри общей транзакции создания stage, если это необходимо.
Это разрешение сохраняется; повторно запрашивать его не требуется.

`scripts.run_stage` принимает явный флаг `--allow-creator-set`.
Без флага отсутствие SET по-прежнему останавливает запуск до DDL.
С флагом исполнитель проверяет совпадение session_user/current_user,
отсутствие целевых схем/роли и права создателя. Если SET уже доступен,
дополнительный GRANT не выполняется. Иначе после создания новой роли
исполняется одна фиксированная команда и проверяются SET=true, INHERIT=false.
Перед тестами дополнительно проверяется фактическая ограниченная роль.
Параметры `--inspect` и `--allow-creator-set` несовместимы.

Исходные три SQL-файла и их закреплённые контрольные суммы не изменены.
Дополнение задаётся фиксированной строкой `CREATOR_SET_SQL` в исполнителе;
произвольный SQL-файл для выдачи прав не принимается.
Предложение `creator_set_role.proposed.sql` остаётся историческим материалом.

При успехе фиксируются только пустые stage-объекты и согласованное членство.
Вымышленные учебные данные откатываются. При ошибке до COMMIT откатываются
также схемы, роль и членство. Неопределённый результат COMMIT требует отдельной
инспекции, без слепого повтора. Runtime остаётся NOLOGIN и без BYPASSRLS.

Повторно запускать создание не нужно: для уже существующих объектов использовать
только `--inspect`. Полный откат DDL и GRANT при искусственной ошибке проверен
локально; в настоящем Supabase прошёл успешный сценарий с откатом учебных данных.

Добавлена локальная форма с Ctrl+V и кнопками вставки, выбором CA и скрытым
паролем. Она не запускает веб-сервер, не сохраняет реквизиты, использует
проверенный исполнитель. Перед созданием всегда выполняется read-only
инспекция; ошибка или существующие stage-объекты останавливают запись.
Реквизиты используются в памяти для двух соединений, повторный ввод не нужен.

```powershell
.\.venv\Scripts\python.exe -m scripts.stage_desktop --allow-creator-set
```

Без флага форма позволяет только проверку. URI по-прежнему принимается только
с `[YOUR-DATABASE-PASSWORD]`, а пароль передаётся отдельным скрытым полем.

Безопасная команда после полученного разрешения:

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\academy ai'
$stageCa = Read-Host 'Полный путь к CA-сертификату Supabase'
.\.venv\Scripts\python.exe -m scripts.run_stage --ca-file $stageCa --allow-creator-set
```

Для предварительного чтения заменить `--allow-creator-set` на `--inspect`.
URI вводится с буквальным `[YOUR-DATABASE-PASSWORD]`, пароль — отдельно скрыто.
Не отправлять реквизиты в чат, не сохранять их в аргументах или логах.

## Render и общий прогресс Windows/iPhone

Существующий `render.yaml` прошёл проверку актуальной официальной JSON Schema:
<https://render.com/schema/render.yaml.json>.
Два сервиса: Free Docker API и Static Site, автоматические deploy выключены,
новой базы Render, диска и автоматических миграций нет.
Ветка соответствует текущей. Секреты не прописаны во frontend.
Правило `/api/*` остаётся rewrite.

До публикации остаются: реальный API-host вместо REPLACE-API-HOST,
отдельно одобренные рабочие схемы и runtime-реквизиты, доверенный CA в Secret
Files, origin и Supabase Auth Redirect URL. Рабочую базу нельзя подменить stage:
stage — репетиция структуры и ограничений, приложение использует обычные схемы.

После отдельного разрешения на рабочую миграцию/импорт, push и публикацию:
свежая резервная копия → импорт копии нужного 40 XP-профиля в пустой аккаунт →
сверка таблиц/XP → запуск → один аккаунт на Windows/iPhone → повтор офлайн-попытки
без удвоения → выход и изоляция другого аккаунта. Реальный iPhone и CDN Render
в этом локальном прогоне не проверялись. Будущие виджеты опираются на ту же
серверную статистику; новая независимая база для них не нужна.

Источники: [PostgreSQL GRANT](https://www.postgresql.org/docs/17/sql-grant.html),
[Render Blueprint](https://render.com/docs/blueprint-spec),
[Render rewrites](https://render.com/docs/redirects-rewrites).

Платные операции, push, публичное размещение, изменения public/auth/storage,
миграции рабочего профиля и перенос настоящих 40 XP не выполнялись.
