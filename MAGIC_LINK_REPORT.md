# Academy AI V5 — Magic Link: отчёт

Дата: 18 ноября 2026 года. Ветка `feature/academy-ai-v2`.

## Реализация

Сохранены существующие Supabase Auth, opaque server sessions, HttpOnly cookie, refresh/expiry/logout и разделение пользователей. Схемы SQLite/PostgreSQL не менялись.

- `POST /api/auth/link` отправляет запрос Supabase OTP с PKCE S256 challenge и фиксированным redirect_to на `/auth/callback`. Использует прежние ограничения частоты и не раскрывает наличие аккаунта.
- Случайный verifier хранится только в короткой HttpOnly SameSite=Strict cookie с путём `/api/auth`, сроком 600 секунд и Secure при HTTPS. HTTP разрешён существующей конфигурацией только для loopback-разработки; production по-прежнему требует HTTPS и PostgreSQL.
- `POST /api/auth/exchange` принимает одноразовый auth code, получает verifier из cookie, вызывает Supabase `token?grant_type=pkce`, затем проверяет identity через `/auth/v1/user`. Создание сессии использует общий существующий механизм для SQLite и PostgreSQL. Старый локальный handle отзывается, verifier удаляется после успеха.
- React захватывает callback до монтирования приложения, удаляет параметры из адреса, выполняет один обмен даже в StrictMode и открывает `/#account`. До окончания входа учебное приложение/синхронизация не монтируются. Коды и токены не сохраняются в localStorage, sessionStorage или IndexedDB.
- Вход по числовому OTP сохранён как дополнительный способ. Стандартный Magic Link выбран по умолчанию.
- Старые implicit-ссылки с access/refresh tokens отвергаются, URL очищается. Произвольные error_description и redirect-параметры не отображаются и не используются для навигации.
- Для callback добавлены маршрут FastAPI и no-store в FastAPI/Render; HTML содержит referrer-policy no-referrer. Service Worker продолжает отдавать публичную оболочку, не кешируя auth API или URL callback с кодом.

Реализация соответствует HTTP-контракту официального Supabase Auth SDK: `/otp?redirect_to=...`, `code_challenge_method=s256`, затем `/token?grant_type=pkce` с auth_code/code_verifier. Собственное хранение паролей или криптографический протокол не добавлялись.

## Данные и ограничения

Проверенная резервная копия: `backups/magic-link-20261118T024042Z/database.db`; исходные строки сохранены в `rows-before.json`. Финальная сверка всех строк 21 таблицы и integrity/foreign_key проверки подтверждают сохранность рабочей SQLite. Новые ответы писались только в отдельные тестовые базы. Старые аккаунты, учебные результаты, XP и офлайн-namespace не объединяются и не перезаписываются.

PKCE требует тот же браузер и устройство. Приложение хранит один ожидающий запрос на браузер; новое письмо заменяет предыдущий запрос. Ожидание ограничено 10 минутами. Старые письма без PKCE необходимо заменить новым запросом из приложения. При потере ответа после одноразового обмена может потребоваться новый вход.

Бесплатный встроенный Supabase SMTP ограничивает получателей и частоту. Эти ограничения не обходятся. Локальный вход использует SQLite-профили на этом компьютере и сам по себе не означает опубликованную облачную синхронизацию.
