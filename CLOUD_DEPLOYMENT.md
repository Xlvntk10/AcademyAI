# Academy AI V4.5 — подключение облака

Проверено по документации провайдеров 5 ноября 2026 года. Все описанные действия размещения выполняются пользователем после отдельного решения о публикации.

## Архитектура

Основная конфигурация `render.yaml` запускает один Render Free Web Service. Docker собирает React и запускает FastAPI, который отдаёт интерфейс и `/api` с одного HTTPS-адреса. Cookie сессии остаётся first-party, HttpOnly, Secure, SameSite=Strict. Это выбранный для первого размещения вариант, включая Safari на iPhone.

Supabase предоставляет PostgreSQL и Email OTP. FastAPI проверяет access token через защищённый запрос `/auth/v1/user` к выбранному проекту Supabase. Обновление токенов выполняется на сервере. Браузер получает случайный идентификатор сессии в cookie. В PostgreSQL сохраняется его SHA-256, токены провайдера находятся в закрытой схеме `academy_auth`. Для обычной работы нужен publishable key. Ключи `service_role` и секрет подписи JWT приложению не требуются.

Все 21 учебная таблица находятся в схеме `academy`. В PostgreSQL добавлены `user_id`, составные первичные/внешние ключи, уникальности в пределах владельца и принудительная RLS. SQLModel использует прежние модели. Каждая транзакция получает проверенного владельца через `SET LOCAL`, после завершения значение сбрасывается. Сессия ORM обслуживает один аккаунт. Новые обработчики обязаны использовать существующую зависимость `get_session`.

Учебный контент пока копируется каждому владельцу. Это сохраняет исходные ID, версии, хеши уроков и старые подтверждения попыток. Дополнительное место учитывается в лимите базы. XP, streak и освоение тем вычисляются из подтверждённых записей. Демонстрационные попытки сохраняются отдельно от учебных прохождений.

Устройства хранят скачанные уроки, черновики и очередь в IndexedDB своего аккаунта. Сервер подтверждает результаты, сериализует запись одного владельца и повторно возвращает прежний результат для того же UUID. Устаревшая редакция плана возвращает 409. Изменение плана требует `If-Match`. Синхронизация происходит при открытом приложении и доступном сервере.

## Что подготовить

- Supabase Free project, его Project URL и `sb_publishable_…` key.
- Из раздела Connect — адрес **Session pooler**, порт 5432 и project reference. Такой вариант подходит для IPv4. Пароли в URL должны быть percent-encoded. Подключения поддерживают TLS, production требует `sslmode=require`, `verify-ca` или `verify-full`. При использовании `verify-full` настройте доверенный сертификат по инструкции Supabase. [Подключения PostgreSQL](https://supabase.com/docs/guides/database/connecting-to-postgres)
- Отдельный пароль роли `academy_runtime` и административный URL для обслуживания.
- Будущий HTTPS-адрес Render для `ACADEMY_PUBLIC_ORIGIN`.
- Для каждого переносимого профиля — путь к SQLite и проверенный UUID его владельца из Supabase Authentication → Users.
- Email для входа и выбранный способ доставки писем.

Секреты следует вводить в локальные переменные окружения и Render Environment. Файлы `.env` автоматически приложением не загружаются. Пример находится в `deploy/.env.example`. React получает только публичный режим `VITE_ACCOUNT_MODE=supabase`.

## Supabase Auth и почта

1. Включите Email provider, подтверждение email и регистрацию, если она нужна.
2. Укажите HTTPS-адрес приложения в Site URL. При необходимости добавьте тот же разрешённый адрес в Redirect URLs.
3. В шаблонах Email OTP/Magic Link и Confirm signup выведите `{{ .Token }}`. Интерфейс принимает числовой одноразовый код. Восстановление доступа выполняется новым кодом на прежний email.
4. Проверьте доставку письма на собственный адрес перед приглашением других пользователей.
5. Сохраните схемы `academy`, `academy_auth`, `academy_migrations` закрытыми для Supabase Data API. Приложение работает через FastAPI и отдельную роль PostgreSQL.

Встроенный SMTP Supabase отправляет письма только адресам участников организации и ограничен двумя письмами в час. Для произвольных пользователей требуется собственный SMTP. Его бесплатность и возможная стоимость домена зависят от выбранного поставщика. Настройка транспорта почты выполняется в Supabase. [Ограничения SMTP](https://supabase.com/docs/guides/auth/auth-smtp)

## Миграция PostgreSQL

Остановите запись в переносимые профили. Для первого запуска используйте пустые Academy-схемы. Облачная история Alembic находится в `migrations/cloud`, её версия — `cloud_0001`. SQLite продолжает использовать `0009_offline_sync`.

Из PowerShell в корне существующего проекта выполните подготовку окружения. `Read-Host -AsSecureString` позволяет ввести административный URL без сохранения его буквального значения в истории команд.

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\academy ai'
$cloudSecret = Read-Host 'Административный PostgreSQL URL' -AsSecureString
$env:MIGRATION_DATABASE_URL = [System.Net.NetworkCredential]::new('', $cloudSecret).Password
.\.venv\Scripts\python.exe -m scripts.migrate_cloud
```

Если Academy-схемы уже существуют, предварительно создайте резервную копию командой из раздела ниже. Автоматического запуска миграций при старте API нет.

В SQL Editor Supabase создайте свежую роль с безопасными атрибутами по умолчанию. Задайте сильный пароль через защищённый инструмент управления ролями или интерактивную команду `\password academy_runtime` в psql.

```sql
CREATE ROLE academy_runtime LOGIN NOINHERIT;
```

Затем выполните содержимое `deploy/grant_runtime.sql` от владельца миграций. Роль получает доступ к данным и последовательностям, без изменения структуры. Проверьте атрибуты и отсутствие членства в повышенных ролях. При небезопасной роли FastAPI откажется запускаться. [Управление ролями Supabase](https://supabase.com/docs/guides/database/postgres/roles)

```sql
SELECT rolname, rolsuper, rolbypassrls, rolcreaterole
FROM pg_roles WHERE rolname = 'academy_runtime';
```

Все три флага должны быть `false`. В `DATABASE_URL` Render используйте имя `academy_runtime.PROJECT_REF` для session pooler и пароль этой роли. Административный `MIGRATION_DATABASE_URL` хранится на машине обслуживания.

## Перенос существующего прогресса

1. Сначала сопоставьте каждый файл SQLite с владельцем Supabase. Сохраните этот список локально.
2. Создайте или найдите соответствующего пользователя в Supabase Authentication. Выполните импорт до первого входа этого пользователя в облачный Academy AI. Если профиль назначения уже создан, команда остановится. Автоматическое слияние двух историй требует отдельной процедуры.
3. Проверьте импорт на отдельной тестовой базе. Затем выполните его в целевой базе во время обслуживания, когда API остановлен.

```powershell
# Подставьте проверенный UUID из Supabase Authentication.
.\.venv\Scripts\python.exe -m scripts.import_cloud `
  --source '.\database.db' `
  --user-id 'UUID-ВЛАДЕЛЬЦА' `
  --backup-dir '.\backups\cloud-import'
```

Для V4 повторите команду с файлом `UUID.db` каждого аккаунта. Команда создаёт SQLite backup API-копию, проверяет integrity/foreign keys, переносит данные одной транзакцией и сравнивает каждую строку. Исходная SQLite сверяется повторно перед commit. При несовместимой схеме или существующем профиле перенос прекращается. Источник должен быть подготовлен до SQLite-ревизии 0009, при необходимости обновляйте отдельную копию существующей командой `scripts.prepare_db`.

UUID пользователей Supabase остаются у провайдера. Локальная таблица владельцев связывает их с учебными записями. Старые SQLite-cookie сессии не импортируются, на устройствах потребуется вход. Сохранённые server_id, UUID попыток, версии уроков и подтверждения позволяют безопасно повторять уже отправленные результаты.

При переходе с localhost на новый HTTPS-origin браузер создаст отдельное хранилище сайта. До переключения отправьте очередь со старого адреса и экспортируйте оставшиеся ответы. Автоматический перенос IndexedDB между адресами пока отсутствует.

## Размещение Render

После разрешения на публикацию загрузите проверенные коммиты в свой существующий Git-репозиторий и подключите его к Render. В этой сессии push и публикация не выполнялись.

1. Используйте Blueprint `render.yaml` или Web Service с Dockerfile. Выберите **Free**, один экземпляр. База хранится в Supabase.
2. Укажите пять значений из `deploy/.env.example`. Production-проверки требуют PostgreSQL, TLS и HTTPS-origin.
3. Docker собирает frontend, устанавливает `requirements-cloud.txt`, запускает Uvicorn на `$PORT`. Миграция и права роли должны быть готовы заранее.
4. Проверьте `/api/health`, вход, сохранение урока, выход и второй независимый браузер. После этого добавляйте приложение на экран телефона.
5. Для Windows откройте HTTPS-адрес в Edge/Chrome и установите приложение через меню браузера. Для iPhone откройте адрес в Safari, используйте «Поделиться» → «На экран Домой».
6. Скачайте урок, дождитесь готовности офлайн-оболочки, закройте приложение, отключите сеть и откройте его через иконку. После восстановления связи проверьте подтверждение очереди и тот же XP на втором устройстве.

### Отдельный Render Static Site

Подготовлен `deploy/render-static.yaml`. Укажите фактический API-host в правиле `/api/*`, а в backend — origin Static Site. Следующее правило обслуживает маршруты React. Сборка выполняется командами `npm --prefix frontend ci` и `npm --prefix frontend run build`.

Документация Render описывает внешние URL для rewrite. Перед переключением обязательно проверьте сохранение метода POST, тела запроса, заголовков `Origin`, `If-Match`, `X-Academy-Account`, передачу `Set-Cookie`/`Cookie` и отсутствие кеширования `/api`. Эти особенности реального Render proxy локально не проверены. Основной вариант с одним Web Service обходит эту зависимость. [Rewrites Render](https://render.com/docs/redirects-rewrites)

## Стоимость и ограничения

Ориентир для личного использования — **0 ₸ в месяц** в пределах Free и при подходящей бесплатной доставке OTP. Пользовательский домен для адреса `onrender.com` не требуется. Тарифы и квоты следует повторно проверить перед включением ресурсов.

- Supabase Free предоставляет 500 MB базы на проект. Возможна приостановка неактивного проекта. Контролируйте размер, особенно при росте количества аккаунтов. [Тарифы Supabase](https://supabase.com/pricing)
- Render Free засыпает после 15 минут без входящего трафика. Пробуждение занимает примерно минуту. Доступно 750 instance-hours на workspace в месяц. Действуют лимиты трафика и сборок. Диск временный, поэтому прогресс хранится в Supabase. Бесплатный Render PostgreSQL имеет ограниченный срок жизни и в этой архитектуре не используется. [Render Free](https://render.com/docs/free)
- На Free нет гарантии постоянной доступности. В интерфейсе есть повторное подключение, офлайн-библиотека и очередь. Для первого входа, подтверждения XP и синхронизации двух устройств требуется доступный сервер и Supabase Auth.
- Нативные виджеты, push после закрытия приложения и облачное хранение записей Speaking остаются будущими задачами.

## Резервные копии и откат

Используйте утилиты PostgreSQL той же или более новой основной версии, чем сервер. Архив содержит личные данные и серверные токены сессий. Храните его в приватном каталоге, резервную копию — отдельно от рабочего компьютера. На автоматическое восстановление Free-тарифа эта процедура не опирается.

```powershell
# pg_dump / pg_restore доступны в PATH, либо передайте --bin-dir.
.\.venv\Scripts\python.exe -m scripts.cloud_backup backup '.\backups\academy-before-release.dump'
```

Команда создаёт новый архив трёх Academy-схем и проверяет его чтение. Существующий файл защищён от перезаписи. Supabase Auth хранит пользователей отдельно, в архив Academy его схема не входит.

Порядок отката при проблеме с данными или миграцией

1. Остановите API и сохраните архив текущего состояния, даже если оно повреждено.
2. Подготовьте отдельную пустую PostgreSQL в том же доверенном контуре и того же проекта Auth. Укажите её административный URL в `MIGRATION_DATABASE_URL`.
3. Восстановите проверенный архив. Команда откажется работать поверх существующих Academy-схем.

```powershell
.\.venv\Scripts\python.exe -m scripts.cloud_backup restore '.\backups\academy-before-release.dump'
```

4. Повторно примените `deploy/grant_runtime.sql`. Сверьте владельцев, количество строк, реальные результаты и `/api/health` под runtime-ролью.
5. Переключите `DATABASE_URL` на восстановленную базу и совместимый коммит приложения. Сохраните проблемную базу для разбора. Возврат к сохранённой SQLite возможен как отдельный локальный режим, но новые облачные результаты потребуют отдельного переноса.
6. Для ошибки только в интерфейсе верните предыдущую проверенную сборку без отката базы. Устройства должны принять обновление PWA.

Накопленные после backup записи требуют сверки с сохранённой текущей базой. Автоматического обратного переноса PostgreSQL → SQLite и автоматического слияния двух баз пока нет.
