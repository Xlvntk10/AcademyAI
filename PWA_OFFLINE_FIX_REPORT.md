# Academy AI V3: исправление холодного офлайн-запуска

Дата: 5 ноября 2026 года. Ветка: `feature/academy-ai-v2`. Исходный коммит: `545302a`.

## Результат и границы проверки

Воспроизведена пустая страница старой сборки после закрытия вкладки и остановки frontend. Исправленная сборка открылась в новой вкладке при полностью остановленных тестовых frontend и backend. Работают интерфейс, переходы по `/today`, `/learn`, `/plan`, `/progress`, сохранённый урок, восстановление черновика и очередь. После возвращения серверов результат подтверждён сервером и пережил обновление страницы.

Это проверка во встроенном браузере ChatGPT на Windows. Закрытие вкладок и создание новой вкладки **не является полным перезапуском процесса браузера**. Доступный интерфейс управления этим браузером не предоставляет перезапуск процесса. Полное завершение/запуск браузера, запуск установленного приложения с иконки, установка PWA и настоящий телефон в этом исправлении **не проверены**. Автоматический тест нового экземпляра Service Worker также не заменяет эти проверки.

## Причина

Vite preview возвращает статические ресурсы с `Vary: Origin`. Запросы `cache.addAll()` при установке Service Worker и запросы ES-модулей/стилей с `crossorigin` несут разные заголовки `Origin`. Старый обработчик искал `cache.match(event.request)` с обычным сравнением `Vary`. Поэтому файл мог присутствовать в Cache Storage, но поиск возвращал промах. Следующий сетевой запрос при выключенном сервере не мог загрузить JavaScript. Пустой `<div id="root">` оставлял белую/пустую страницу.

Различие заголовков подтверждено HTTP-запросами к локальному Vite. Регрессионный тест воспроизводит промах старого поиска и успешную выдачу файла исправленным worker. До исправления браузер показал пустую страницу; после исправления тот же сценарий открывает приложение. Полного сетевого журнала старого браузерного сбоя нет, поэтому нельзя исключить другие причины сходного симптома на отдельных устройствах.

Поведение `Vary` описано в [MDN: Cache.match](https://developer.mozilla.org/en-US/docs/Web/API/Cache/match). Опция `ignoreVary` применяется только к публичным файлам сборки, а не к API или личным результатам.

Дополнительные проблемы: маршрутизатор читал только hash, а при ошибке первого API-запроса основная область могла оставаться без содержимого. Регистрация PWA также зависела от успешного сетевого запроса нового `sw.js`, хотя ранее установленный worker уже мог работать автономно.

## Изменения

- `frontend/pwa-worker.js`: поиск публичных ресурсов по каноническому пути с `ignoreVary`; HTML и ресурсы одной сборки; сохранённые ресурсы предыдущей сборки для старых вкладок; резервный офлайн-HTML при отсутствии основной оболочки. Запросы `/api`, `/api/*`, чужих источников и изменения данных не кешируются. Ожидание активации и защита обновления при нескольких вкладках сохранены.
- `frontend/pwa-plugin.ts`, `frontend/public/offline.html`: самостоятельный офлайн-экран включён в precache и хеш версии. В production precache содержит 11 файлов: HTML, JS, CSS, манифест, иконки и резервный экран.
- `frontend/index.html`: начальный текст вместо пустого root; если React не загрузился за 6 секунд, появляются объяснение и ссылка повторного открытия. Этот экран не требует JS/CSS из внешних файлов.
- `frontend/src/pwa.ts`: привязка к установленной регистрации до сетевой регистрации; готовность проверяется у worker, который действительно контролирует документ; ошибка обновления без сети не отменяет готовность установленного кеша.
- `frontend/src/App.tsx`: поддержка прямых четырёх маршрутов с сохранением hash-навигации; обновление данных при событии `online`; понятное содержимое при недоступности API.
- `frontend/src/Offline.tsx`: офлайн-экран со списком уроков из IndexedDB, переходом к черновикам и очереди либо объяснением, как заранее скачать уроки. План и общая статистика без сервера не выдумываются.
- `frontend/src/pwa-cold-start.test.ts`, `frontend/src/pwa-registration.test.ts`, `frontend/src/offline.test.tsx`: новые регрессии кеша, регистрации и четырёх маршрутов.
- `README.md`, этот отчёт: актуальные результаты и ограничения.

Web App Manifest проверен: `id` и `scope` — `/`, старт — `/#today`, есть standalone, иконки и shortcuts. Менять его для этого исправления не потребовалось. Схема IndexedDB, формат очереди, UUID попыток, серверная проверка, правила XP, учебные данные и миграции не менялись. Новых зависимостей нет.

## Как получить исправленную версию без потери ответов

Не очищай данные сайта, Cache Storage или IndexedDB для обновления. Открой тот же адрес, порт и профиль браузера, где сохранены уроки: `localhost` и `127.0.0.1`, разные порты и браузеры имеют разные хранилища.

Терминал 1, PowerShell:

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\academy ai'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Терминал 2:

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\academy ai\frontend'
npm.cmd run build
npm.cmd run preview
```

Открой `http://127.0.0.1:4173`. Пока серверы работают, обнови страницу для обнаружения нового worker, затем закрой все вкладки и окна установленного Academy AI этого адреса и открой его снова. Если старый worker показывает пустую страницу, обновление онлайн и закрытие всех его вкладок позволяют новому worker активироваться; именно так обновлена старая сборка в проверке. Альтернатива при работающем интерфейсе — штатное уведомление об обновлении в настройках, завершив сохранение текущих ответов.

В локальной библиотеке дождись сообщения, что worker подтвердил наличие оболочки в кеше. Скачай урок. Это подтверждение состава кеша, а не гарантия поведения каждого устройства.

## Оставшаяся ручная проверка полного холодного запуска

1. Подготовь production-версию и скачанный урок по инструкции выше. При желании установи PWA через меню Edge/Chrome. Не используй dev-сервер 5173 для этой проверки.
2. Останови frontend и API через `Ctrl+C`. Сохрани другую работу и полностью заверши браузер и окна PWA, включая фоновые процессы через штатные настройки браузера.
3. Запусти браузер или установленное приложение снова с тем же профилем и origin, без серверов. Проверь `/today`, `/learn`, `/plan`, `/progress` и локальный урок.
4. Введи ответы, закрой и повторно открой приложение, проверь черновик; заверши попытку и проверь сохранение очереди.
5. Верни серверы, отправь очередь, обнови страницу и проверь, что результат сохранился, а повторная отправка не добавляет XP.
6. Повтори на настоящем телефоне через заранее настроенный доверенный HTTPS. HTTP по LAN-адресу обычно не даёт Service Worker, а localhost телефона не указывает на компьютер. Эта работа не настраивала сертификаты и не публиковала сервер.

Если браузер удалил хранилище или worker никогда не устанавливался, приложение не сможет автономно получить свои файлы. Резервный HTML помогает, когда worker ещё существует; если браузер удалил и его, остаётся стандартная страница ошибки браузера до подключения к серверу.
