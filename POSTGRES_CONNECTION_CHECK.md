# Проверка Supabase Session pooler без миграций

Подготовлено 19 ноября 2026 года. Дополнено безопасной диагностикой подключения и видимым вводом URI с плейсхолдером. Команда проверяет только соединение через тот же драйвер, который использует FastAPI. FastAPI не запускается; приложение, модели, Alembic и SQLite не импортируются и не открываются.

## Драйвер и безопасный формат

В проекте установлен `psycopg[binary]==3.2.13` (Psycopg 3), SQLAlchemy использует схему `postgresql+psycopg://`. Текущая libpq — 16.9. Обычный URI Supabase `postgresql://...` поддерживается командой и существующим make_engine.

Формат будущего DATABASE_URL (только пример, не готовый пароль):

```text
postgresql+psycopg://postgres.PROJECT_REF:URL_ENCODED_PASSWORD@POOLER_HOST:5432/postgres?sslmode=verify-full&sslrootcert=URL_ENCODED_CA_FILE_PATH
```

Сохраняйте host и пользователя точно из Session pooler URI: у пользователя обычно есть суффикс проекта. Пароль внутри готового URI должен быть URL-encoded, как и путь сертификата в query. В интерактивной проверке ниже пароль вводится отдельно обычным текстом со скрытием символов: вручную кодировать `@`, `:`, `/`, `%`, `#` не нужно. Скрипт разбирает URI и безопасно формирует URL/параметры в памяти.

**Пока не меняйте DATABASE_URL запущенного FastAPI и не запускайте его против неподготовленной облачной базы.** В приложении ACADEMY_DATABASE_URL имеет приоритет над DATABASE_URL. Новая проверка полностью отдельная и не использует ACADEMY_DATABASE_URL. Перенос данных и создание ограниченной runtime-роли — отдельный этап.

## Точные шаги PowerShell

1. В Supabase → **Connect** выберите **Session pooler**, **Type URI**, порт **5432**. Скопируйте URI. Перед вставкой в терминал замените поле пароля на точный `[YOUR-DATABASE-PASSWORD]`. Другие плейсхолдеры и настоящий пароль в видимом URI не принимаются. Настоящий пароль команда запросит отдельно скрыто. Не присылайте реквизиты в чат, не вставляйте их в исходный код, `.env`, команды или документы.

2. В **Database Settings** скачайте CA/SSL certificate проекта. Сохраните, например, в `C:\Users\user\Downloads\supabase-ca.crt`. Используйте фактическое имя скачанного файла; сертификат публичный, пароль в него не вставляется. `verify-full` проверяет сертификат и соответствие имени сервера. Официальная инструкция для Session pooler: https://supabase.com/docs/guides/database/psql

3. Откройте обычный PowerShell-терминал VS Code, не Debug Console. Выполните:

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\academy ai'
$caPath = Read-Host 'Полный путь к скачанному CA-сертификату Supabase'
.\.venv\Scripts\python.exe -X utf8 -m scripts.check_postgres --ca-file "$caPath"
$LASTEXITCODE
```

4. Когда появится **Session pooler URI**, вставьте URI из шага 1 и нажмите Enter. **Этот ввод видимый**: вы увидите вставленную строку. Это ввод в программу, а не команда PowerShell. Пример формата:

```text
postgresql://postgres.PROJECT_REF:[YOUR-DATABASE-PASSWORD]@POOLER_HOST:5432/postgres
```

Видимый ввод отображается терминалом до проверки, поэтому заранее замените настоящий пароль плейсхолдером. Программа не сохраняет URI в лог и не повторяет его в ошибках. Если в поле пароля не точный плейсхолдер, появится `[URI_PLACEHOLDER]` и выполнение остановится без подключения. Не включайте запись терминала при работе с секретами.

5. Когда появится **Пароль базы PostgreSQL**, вставьте настоящий пароль базы, заданный при создании проекта, и нажмите Enter. Это не пароль аккаунта Supabase, не publishable key и не service_role key. Символы пароля не отображаются. Не вводите сюда плейсхолдер — нужен настоящий пароль базы без URL-кодирования.

6. При успешной проверке:

```text
OK [CONFIG]: URI разобран; CA-файл найден и прочитан. Проверка TLS: verify-full.
OK: psycopg 3.2.13; TLS включён, сертификат и имя сервера проверены (verify-full).
SELECT 1 = 1. Транзакция только для чтения завершена откатом. Миграции не запускались.
0
```

Ноль — код успешного завершения. Это подтверждает соединение вашего компьютера с Session pooler, но не готовность схемы Academy AI, Auth или разграничения прав. Соединение от клиента до pooler проверяется на стороне клиента, а не выводом pg_stat_ssl о другом участке соединения.

## Что именно делает команда

- Принимает только PostgreSQL URI, Session pooler port 5432 и доверенный CA-файл.
- Принудительно включает `sslmode=verify-full`, TLS не ниже 1.2; не переходит на незашифрованное соединение при ошибке сертификата.
- Проверяет `connection.pgconn.ssl_in_use` до выполнения SQL.
- Начинает транзакцию только для чтения, выполняет **SELECT 1**, проверяет `(1,)`, делает rollback и закрывает соединение. COMMIT, CREATE, ALTER, INSERT, UPDATE, DELETE и миграций в коде нет.
- Не повторяет URI, host, пользователя, пароль или полный текст ошибки драйвера в своих сообщениях. Только введённый шаблонный URI виден при вводе в терминале. Не создаёт логов, файлов конфигурации, таблиц или записей.
- Для Windows и CA-пути с кириллицей временно копирует только публичный сертификат в путь с латинскими символами. Содержимое не меняется; временная копия удаляется при успехе и при ошибке. Исходный сертификат сохраняется.
- Не сохраняет реквизиты в Git, файлы или переменные окружения. Реквизиты нужны процессу в памяти только на время проверки; они не передаются в аргументах запуска. При невозможности скрытого ввода пароля команда прекращает работу, а не включает отображение пароля.

Для уже подготовленной временной переменной DATABASE_URL доступен дополнительный режим:

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.check_postgres --from-env --ca-file "$caPath"
```

Он читает только DATABASE_URL, не меняет её и не печатает. Этот режим никогда не отображает DATABASE_URL; ограничение плейсхолдера относится к видимому интерактивному вводу. Для первой проверки используйте интерактивный режим выше: он не требует создавать секретную переменную. `.env` автоматически не загружается. Путь --ca-file имеет приоритет над sslrootcert из URI.

## Если проверка не прошла

Команда выводит этап и фиксированный код причины. Она анализирует SQLSTATE и известные сообщения драйвера внутри процесса, но не печатает исходный текст, traceback, host, username, пароль или URI. Неизвестная ошибка честно помечается UNKNOWN и не объявляется неверным паролем.

| Код | Значение и следующий шаг |
| --- | --- |
| URI_PLACEHOLDER | В видимом URI поле пароля не равно точному [YOUR-DATABASE-PASSWORD]. Замените его перед повторным запуском; строка не повторяется. |
| CA_PATH | Не найден файл/ошибка пути. Парные внешние кавычки из Read-Host теперь удаляются автоматически, в том числе «умные» двойные кавычки. |
| CA_ACCESS / CA_TEMP_COPY | Нет доступа к исходному файлу или временной папке. |
| CA_FORMAT | Файл существует, но не является читаемым PEM CA. Скачайте правильный сертификат из Database Settings. |
| CA_PATH_ENCODING | Windows-драйвер не поддержал путь; автоматическая временная копия также не получила латинский путь. Сохраните публичный сертификат по доступному пути без кириллицы. |
| URI_FORMAT / URI_USER / URI_PORT / URI_OPTIONS | Ошибка URI, пользователя Session pooler, порта или параметров. Скопируйте URI с placeholder пароля целиком из Connect. |
| TLS_MODE | В URI явно задан более слабый SSL mode; оставьте verify-full либо удалите параметр — команда включит verify-full сама. |
| AUTH_REJECTED | Сервер отклонил пользователя/пароль. Проверьте пароль БД и username с суффиксом проекта. Это не всегда означает, что неверен именно пароль. |
| POOLER_IDENTITY | Pooler не нашёл проект/пользователя: проверьте скопированные host и username, не угадывайте регион или индекс aws-0/aws-1. |
| TLS_HOSTNAME | Имя сервера не соответствует сертификату; проверьте host, не заменяйте его IP. |
| TLS_CERTIFICATE | Сертификат сервера не прошёл проверку: возможны неверный CA, цепочка, срок действия или время компьютера. |
| TLS_CA_LOAD | Драйвер не смог загрузить CA. Исходный файл может быть удалён/недоступен после предварительной проверки. |
| TLS_REQUIRED / TLS_HANDSHAKE | TLS не согласован либо ошибка рукопожатия. Не отключайте TLS. |
| DNS / TIMEOUT / CONNECTION_REFUSED / NETWORK | Ошибка имени, ожидания или сети. Доступность TCP-порта не означает успешную проверку TLS и пароля. |
| DATABASE / ACCESS_RULE / PERMISSION | Неверное имя базы, запрет правилами доступа или недостаток прав. |
| POOL_LIMIT / SERVER_UNAVAILABLE / AUTH_PROTOCOL | Ограничение соединений, состояние сервера либо серверной процедуры аутентификации. |
| UNKNOWN | Безопасно классифицировать ошибку не удалось. Диагностика не угадывает причину. |

Пример сообщения, которое можно безопасно прислать для дальнейшей помощи:

```text
FAIL [CONNECT/TLS_CERTIFICATE]: Не прошла проверка сертификата сервера. ...
```

CONNECT включает установку TCP, TLS и аутентификацию; SELECT означает, что соединение уже установлено, а ошибка возникла при проверочном запросе. Программа не выдаёт полученное от сервера сообщение с заменённым паролем: она выбирает заранее заданный безопасный текст, поэтому неизвестные варианты реквизитов тоже не попадут в вывод.

### Исправленная обработка пути

При вводе пути через Read-Host внешние кавычки становятся частью значения. Старая версия не удаляла их. Теперь поддерживаются значения как `C:\Users\user\Downloads\ca.crt`, так и `"C:\Users\user\Downloads\ca.crt"`; пароль не обрезается и не меняется.

В локальной проверке также воспроизведена особенность Windows libpq: CA в пути с кириллицей не загружался драйвером, хотя Python читал его. С временной копией того же публичного CA по латинскому пути соединение прошло. Для пути с кириллицей эта совместимость теперь применяется автоматически. Она не меняет trust store, не отключает проверку имени и не заменяет CA на другой сертификат.

Точную причину ошибки вашего Supabase определит повторный запуск; локальное воспроизведение не доказывает, какая именно проблема была в вашем подключении. Не присылайте URI, пароль, содержимое переменных окружения или данные отладчика — достаточно строки FAIL.

## Проверки подготовки

Выполнены **51 целевой тест**, включая видимый ввод URI только с плейсхолдером, скрытый ввод настоящего пароля, отказ неверному URI до подключения, кавычки, кириллицу в пути, неверный PEM, SQLSTATE, классификацию ошибок и удаление временного CA. Прежние проверки сохранены: безопасный разбор URI, специальные символы пароля, запрет SQLite/неверного порта/слабого TLS/дополнительных options, скрытие ошибок, отсутствие COMMIT и отказ от открытого ввода.

Реальная изолированная локальная PostgreSQL также успешно прошла `verify-full` и SELECT 1 под ограниченной ролью. Тестовая база использовала свой отдельный порт, а публичная команда требует 5432. Дополнительно посторонний валидный CA был отклонён с CONNECT/TLS_CERTIFICATE: проверка не отключилась. Миграции не запускались. Собственный тестовый сервер остановлен. Побайтовый SHA-256 рабочей SQLite до и после совпадает.

Настоящий Supabase не проверялся: URI и пароль остаются у пользователя. Приложение не опубликовано, push не выполнялся. Полный набор учебных тестов и frontend-сборка не запускались повторно: учебное приложение не менялось.

Изменение режима ввода проверялось без подключений к PostgreSQL. SQL, TLS verify-full и меры защиты данных не изменены.
