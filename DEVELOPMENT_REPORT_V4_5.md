# Academy AI V4.5 — отчёт о подготовке облака

Работа выполнена 5 ноября 2026 года в существующем репозитории, ветка `feature/academy-ai-v2`.

## Выполнено

- Добавлены `DATABASE_URL`, драйвер psycopg, общий PostgreSQL и прежний режим SQLite. Production требует PostgreSQL с TLS и аккаунты с HTTPS-origin.
- Созданы 21 таблица с `user_id`, составными ключами и принудительной RLS. Контекст владельца действует в пределах транзакции. Runtime-роль проверяется на повышенные права.
- Добавлена облачная история Alembic `cloud_0001`, импорт отдельных SQLite-профилей, проверка каждой строки, резервные копии и восстановление в пустую базу.
- Серверные Supabase-сессии и лимиты входа сохраняются в PostgreSQL. Проверка пользователя выполняется через Supabase Auth, обновление истёкших access tokens сериализовано. CORS допускает один заданный origin, запись требует прежние CSRF-заголовки.
- Проверена синхронизация двух независимых cookie-клиентов, XP/streak, расписания, повторов после потери ответа, одинаковых UUID у разных владельцев и конфликтов редактирования.
- Подготовлены Dockerfile, основной Render Blueprint, отдельный вариант Static Site, production-переменные, инструкция Supabase и отката.
- Улучшены повторное подключение, сообщения о недоступном сервере, состояние очереди в профиле, мобильные поля входа и фон тёмной темы. Обновление PWA доступно на экране входа.

Для первого размещения выбран общий HTTPS-origin React и FastAPI на одном Render Free Web Service. Отдельный Static Site подготовлен как вариант, требующий проверки реального proxy. Учебные материалы хранятся по владельцам, что сохраняет старые ID и версии при переносе. Это увеличивает объём базы при росте числа пользователей.

## Локальный запуск в PowerShell

В новом терминале VS Code запустите прежний локальный режим.

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\applied-is-project-2026'
$env:ACADEMY_AUTH_MODE = 'local'
$env:ACADEMY_ENV = 'development'
$env:ACADEMY_SERVE_FRONTEND = '0'
$env:ACADEMY_DATABASE_URL = 'sqlite:///database.db'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

В другом терминале

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\applied-is-project-2026\frontend'
npm.cmd run dev
```

Откройте `http://127.0.0.1:5173`. Для PWA-проверки локальной production-сборки выполните `npm.cmd run build`, затем `npm.cmd run preview` и откройте `http://127.0.0.1:4173`. Во время этой сессии последняя сборка создана с `VITE_ACCOUNT_MODE=supabase`, для локальной сборки уберите эту переменную в своём терминале перед build. Онлайн-режим приложения всё равно определяется backend.

Обычные проверки из корня проекта

```powershell
.\.venv\Scripts\python.exe -m pytest -ra
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
.\.venv\Scripts\python.exe -m scripts.verify_pwa
```

Без тестовой PostgreSQL первый запуск даёт 64 backend-теста и пропуск 15 интеграционных тестов. Для полного прогона нужны `ACADEMY_TEST_DATABASE_URL` ограниченной роли, `ACADEMY_TEST_ADMIN_URL` администратора, отдельная база с именем, заканчивающимся на `_test`, миграции и grants. Для backup/restore также задайте `ACADEMY_TEST_PG_BIN` с каталогом pg_dump/pg_restore и используйте администратора локального тестового кластера, способного создавать отдельную базу. Тесты добавляют изолированных владельцев и очищают только таблицу лимитов этой тестовой базы.

## Следующий шаг и ограничения

Полная инструкция находится в `CLOUD_DEPLOYMENT.md`. Нужны Project URL, publishable key, Session pooler и пароли ролей, HTTPS-origin, способ доставки OTP, сопоставление SQLite-файлов и UUID пользователей.

Ориентир — 0 ₸ в месяц в пределах Free. Нужно учитывать 500 MB Supabase, возможную паузу неактивного проекта, сон Render через 15 минут, задержку пробуждения, квоты трафика/сборок и ограничение встроенного SMTP двумя письмами в час участникам организации. [Supabase Free](https://supabase.com/pricing), [Render Free](https://render.com/docs/free), [Supabase SMTP](https://supabase.com/docs/guides/auth/auth-smtp)

Настоящий облачный запуск требует отдельного разрешения, настройки провайдеров и проверки на двух реальных устройствах. Смена origin создаёт отдельное браузерное хранилище. До перехода нужно отправить старую очередь и экспортировать остаток. Автоматическое слияние существующих профилей, перенос IndexedDB между адресами и обратная миграция PostgreSQL → SQLite пока отсутствуют.

Откат предусмотрен через проверенный dump в отдельную пустую базу, повторное применение grants и переключение на совместимую версию приложения. Для новых записей после backup потребуется сверка с сохранённой текущей базой. Процедура восстановления проверена локально.
