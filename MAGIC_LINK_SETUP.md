# Вход в Academy AI по Magic Link — локальная настройка

Обновлено 18 ноября 2026 года. Адрес приложения для этой инструкции: **http://127.0.0.1:5173**. Существующий проект и данные сохранены; публикация не требуется. Платный SMTP и AI API не подключаются.

## 1. Что настроить в Supabase

В созданном проекте откройте **Authentication → URL Configuration**:

| Поле | Точное значение |
| --- | --- |
| Site URL | `http://127.0.0.1:5173` |
| Redirect URLs → Add URL | `http://127.0.0.1:5173/auth/callback` |

Сохраните настройки. Не подменяйте `127.0.0.1` на `localhost`: для браузера это разные адреса и разные cookies. Не добавляйте широкие wildcard. Backend сам задаёт адрес возврата из ACADEMY_PUBLIC_ORIGIN; пользователь не может передать произвольный адрес перенаправления. [Документация Redirect URLs](https://supabase.com/docs/guides/auth/redirect-urls).

В **Authentication → Email Templates** оставьте стандартный шаблон **Magic Link** с `{{ .ConfirmationURL }}`. Аналогично проверьте шаблон **Confirm signup** для первой регистрации. Ссылка должна вести через Supabase, а не напрямую на Site URL:

```html
<a href="{{ .ConfirmationURL }}">Войти в Academy AI</a>
```

Не заменяйте её на `{{ .SiteURL }}` или `{{ .RedirectTo }}`: эти адреса сами по себе не подтверждают вход. Числовой OTP не обязателен. Дополнительный способ «Код из письма» остаётся доступен, если в шаблон добавлено `{{ .Token }}`. Подтверждение email оставьте включённым. Если аккаунта ещё нет, разрешите регистрацию пользователей в настройках Email/Auth. [Magic Link и OTP](https://supabase.com/docs/guides/auth/auth-email-passwordless).

Для бесплатного личного теста используйте email владельца/участника команды Supabase. Встроенная отправка рассчитана на тестирование, обычно ограничена **2 письмами в час на проект** и не отправляет произвольным адресам вне команды. Наличие пользователя в Authentication → Users само по себе не делает его участником команды. Если провайдер не разрешает получателя или исчерпан лимит, приложение не может безопасно обойти это ограничение. Платную почту подключать не требуется для проверки на разрешённом адресе. [Ограничения встроенной почты](https://supabase.com/docs/guides/auth/auth-smtp).

## 2. Какие значения взять из Supabase

Понадобятся только **Project URL** вида `https://PROJECT_REF.supabase.co` и **publishable key**, начинающийся с `sb_publishable_`. Их можно найти в настройках подключения/API Keys проекта.

Не используйте service_role, sb_secret, пароль PostgreSQL или JWT secret. Значения вводятся в терминале backend; React их не получает. Приложение не подхватывает `.env` автоматически.

## 3. Запуск в VS Code: два PowerShell-терминала

Остановите прежние процессы на портах 8000 и 5173 через Ctrl+C в их терминалах. Не запускайте две копии сервера на одном порту.

**Терминал 1 — FastAPI:**

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\academy ai'
$env:ACADEMY_ENV = 'development'
$env:ACADEMY_AUTH_MODE = 'supabase'
$env:ACADEMY_PUBLIC_ORIGIN = 'http://127.0.0.1:5173'
$env:ACADEMY_SERVE_FRONTEND = '0'
$env:ACADEMY_DATABASE_URL = 'sqlite:///database.db'
$env:ACADEMY_ACCOUNTS_DIR = "$env:LOCALAPPDATA\AcademyAI\accounts"
$env:SUPABASE_URL = Read-Host 'Project URL Supabase'
$env:SUPABASE_PUBLISHABLE_KEY = Read-Host 'Publishable key sb_publishable_...'
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-access-log
```

Если прежние аккаунты уже использовали другой ACADEMY_ACCOUNTS_DIR, сохраните тот же путь для того же Supabase-проекта. При сообщении, что каталог принадлежит другому Supabase-проекту, укажите новый отдельный каталог, не удаляйте старый. Каталог содержит сессии и личные базы; храните его вне web root и общей файловой синхронизации.

**Терминал 2 — React:**

```powershell
Set-Location 'C:\Users\user\OneDrive\Рабочий стол\academy ai\frontend'
$env:VITE_ACCOUNT_MODE = 'supabase'
Remove-Item Env:ACADEMY_HTTPS_CERT -ErrorAction SilentlyContinue
Remove-Item Env:ACADEMY_HTTPS_KEY -ErrorAction SilentlyContinue
npm.cmd run dev
```

Эти команды выбирают существующий локальный SQLite-режим аккаунтов. Они не мигрируют данные в облако. Supabase используется только для подтверждения входа. Если нужен прежний профиль без аккаунта, команды его запуска сохранены в README.

## 4. Как проверить настоящее письмо

1. В браузере на компьютере откройте **http://127.0.0.1:5173**.
2. Если аккаунта приложения ещё нет, нажмите **«Зарегистрироваться»**. Созданный проект Supabase сам по себе не создаёт учебный аккаунт.
3. Оставьте способ **«Ссылка из письма»**, введите разрешённый email и нажмите **«Получить ссылку»**.
4. Откройте **последнее** письмо и нажмите ссылку в **том же браузере и профиле браузера**, где запросили вход, в течение 10 минут. При необходимости скопируйте ссылку из письма в этот браузер. Не пересылайте её другим людям.
5. Academy AI должна автоматически открыть **«Мой профиль»** с вашим email. В адресе не должно остаться `?code=...` или токенов.
6. Обновите страницу: профиль должен сохраниться. Проверьте открытие уроков; затем нажмите «Выйти из аккаунта» и убедитесь, что появился экран входа.
7. Для второго браузера запросите отдельную ссылку на тот же email из второго браузера. Не переносите между браузерами одну и ту же ссылку.

PKCE связывает запрос входа и ответ Supabase с браузером. Поэтому переход из письма на телефоне не завершит запрос, начатый на Windows. Кроме того, `127.0.0.1` на телефоне означает сам телефон. Для проверки на iPhone позже потребуется доступный ему HTTPS-адрес; публикация сейчас не выполняется. [Ограничение PKCE](https://supabase.com/docs/guides/auth/sessions/pkce-flow).

Если новая учётная запись показывает 0 XP, это не потеря прежней базы. Старый локальный профиль, демонстрационные записи и офлайн-очереди не присваиваются автоматически новому аккаунту. Прежняя `database.db` сохранена. Перенос подтверждённого прогресса выполняется отдельно с проверкой владельца.

## 5. Если вход не получился

- **Письмо не пришло:** проверьте спам, разрешённый email и лимит встроенного SMTP. Не нажимайте отправку многократно: лимиты действуют и в Supabase, и в Academy AI.
- **Открылся другой адрес/порт:** проверьте Site URL, точный Redirect URL и ACADEMY_PUBLIC_ORIGIN; затем запросите новое письмо. Старые письма содержат прежний адрес.
- **Ссылка устарела или браузер не подходит:** запросите новую ссылку и откройте последнее письмо в исходном браузере. Новый запрос заменяет предыдущий verifier; старая ссылка больше не подходит. Проверьте, что cookies разрешены.
- **Ссылка содержит `#access_token=...`:** это старый implicit-вход, запрошенный до обновления или вне Academy AI. Приложение не импортирует такие токены. Запросите новое письмо кнопкой «Получить ссылку».
- **Временная ошибка сети:** на странице входа есть «Повторить подключение». Если одноразовый код уже был использован, но ответ потерялся, откройте главную: если сессия не сохранилась, запросите новое письмо.
- **Страница показывает прежний экран входа:** закройте старые вкладки/обновите установленную PWA через её настройки. Не очищайте IndexedDB и данные сайта ради обновления: там могут оставаться офлайн-ответы.
- **Включён CAPTCHA:** текущий клиент не передаёт captcha_token. Не отключайте защиту для публичного приложения; интеграция CAPTCHA — отдельная задача. Внешний проект в рамках этих работ не менялся.
